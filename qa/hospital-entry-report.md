# 병원 연계 환자 진입 UX 및 이용 동기 강화 — 2026-10-14

## 기존 구조 분석
- 랜딩 `/`의 시작 CTA → `/patient`에서 세션 확인. 토큰이 있으면 기존 `/i?token=…`로 전달.
- 실제 환자 연결은 `inspectPatientInvitation`으로 초대 유효기간/취소 상태를 확인하고, 기존 본인 확인 후 `verifyPatientIdentity`가 세션을 생성하는 방식.
- 환자 화면은 세션의 환자 ID와 병원 ID가 일치하는 기록만 조회. URL의 임의 `patientId`로 실제 인증 환자를 바꾸지 않음.
- 기존 인증은 브라우저 저장 기반 구현. 서버의 운영급 권한 검증을 신설하거나 인증 유효기간을 늘리지 않음.
- 이전 진입 화면은 안내/도움말/체험을 반복 카드로 표시했고, 실제 행동 버튼은 샘플 체험이 가장 강조되어 있었음.

## 변경 전후 동선
| 상태 | 변경 후 |
|---|---|
| 인증 없음 | 가치 메시지 → 병원 링크 이용 안내 CTA → 단계별 링크 여는 방법 |
| 유효한 기존 세션 | `/patient` 진입 시 안내 생략 → 오늘 |
| 정상 초대 링크, 미인증 | 기존 초대 검증 → 기존 본인 확인 → 오늘 |
| 정상 초대 링크, 해당 환자 인증됨 | 기존 일치 검증 → 오늘 |
| 만료/잘못된 링크 | 기존 상황별 오류와 링크 재안내 방법 |
| 세션 만료 | 원본 링크 재이용 및 만료 시 병원 재안내 요청 방법 |
| 환자 ID와 병원 ID 불일치 | 기록을 표시하지 않고 접근 제한 안내 |

## 화면 변경
- ‘오늘의 작은 기록이 회복의 변화를 보여줘요.’와 기록/변화 확인/진료 시 기록 정리의 실제 기능 가치 3개 표시.
- ‘병원에서 안내 링크를 받으셨나요?’ 아래 ‘링크 여는 방법 확인’을 유일한 강조 CTA로 배치. 클릭 시 실제 이용 방법을 펼치고 접음.
- ‘링크를 찾을 수 없나요? 도움말 보기’를 작은 보조 도움말로 변경. 메시지 검색, 최근 원본 링크 확인, 퇴원 안내문의 실제 연락처로 재안내 요청 방법 제공.
- 반복 카드/큰 체험 CTA 제거. 실제 링크 발급·메시지 검색·전송 기능을 가장하는 버튼 없음.
- 랜딩과 보호자 미연결 화면의 공개 체험 유도 제거. 병원 홍보 화면의 공개 데모 CTA는 실제 구현된 병원 로그인 경로로 변경.
- 의료 효과나 병원 자동 전달을 보장하는 문구 추가 없음.

## 데모 접근 정책
- 샘플 기능을 삭제하지 않고 개발 환경(`next dev`)에서만 기존 `/demo/**`로 유지.
- 운영 정적 빌드는 공통 `app/demo/layout.tsx`에서 샘플 클라이언트를 렌더링하지 않음. 기존 환자/병원/가족 샘플 URL도 모두 개발 전용 안내와 정상 이용 경로를 표시.
- 환자/병원 로그인이나 URL 파라미터로 운영 사이트의 데모를 활성화하는 예외 없음.
- 내부 영업·운영 환경에서도 데모를 사용하려면 서버에서 검증하는 별도 내부 접근 제어가 필요. 현재 공개 정적 사이트의 클라이언트 로그인만으로 내부 전용을 보장하지 않음.
- 기존 샘플/실제 기록 저장소 분리는 유지. 기존 데이터 삭제나 마이그레이션 없음.

## 미검증 및 후속 사항
- 실제 병원의 문자/카카오톡 발송 시스템과 운영 환자 데이터, iOS/Safari 및 스크린리더 수동 검증은 미실시. 테스트는 별도 샘플/테스트 세션만 사용.
- 기존 ESLint 플러그인 누락으로 린트는 미검증. 타입 검사와 `next build --no-lint` 결과를 구분하여 보고.
- 본인 확인 및 세션 유지 기간, 초대 발급/재발급 기능은 기존 그대로. 일반 회원가입이나 URL 입력 기반의 우회 인증을 신설하지 않음.
- 서버 인증과 병원별 실제 문의 경로·내부 영업 데모 권한은 별도 개발 항목.
