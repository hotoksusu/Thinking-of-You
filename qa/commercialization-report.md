# 오늘안부 Care 상용화·보안 강화 결과 — 2026-10-26

## A. 착수 진단

[변경 전 시스템 감사](../docs/commercialization-audit.md)를 먼저 작성했다. 운영 Site는 공개 버전 91이며, 앞선 신규 서버 코드는 미배포 상태였다. 기존 환자·병원 UI와 브라우저 저장 기능은 유지했다. 실제 환자 데이터를 조회·개발 DB로 복사하거나 삭제하지 않았다.

주요 차단 요인은 플랫폼 운영자의 전역 임상 접근 예외, 직원 역할·담당자 권한 미구분, 서버 후속 업무/감사/성과 측정 부재, 외부 알림 미연동, 실제 운영 DB·백업·계약·MFA 검증 부재였다. 기존 ‘대상 환자 보기’와 ‘월간 리포트 생성’은 작동 코드가 있었으며 실제 브라우저 동선으로 재검증한다.

- 최종 배포용 단일 ESM Worker 대상으로 서버·보안·백업·SMS 모의 전송·운영 브라우저 15건 통과, 실패 0건. 원본 서버 모듈 테스트 외에 실제 배포 산출물을 재검증했다.

- 실제 SQLite/D1 호환 어댑터의 영속 저장/재접속, 실제 API UI 저장 실패·재시도·중복·수정 충돌, 기관 A/B 조회·변경·다운로드 거절, 직원 배정/회수, 세션 만료·재발급·CSRF·SQL 입력, 부분 DB 실패 rollback, 신호 유지, 통계/CSV와 원본 비교를 검증했다.

## D. 운영 적용·의사결정

실제 Site의 신규 소스 푸시·DB 마이그레이션·배포는 미완료다. 사용자 재설정/계속 요청 이후에도 자동 승인 검토가 쓰기 자격증명 전달을 거절했다. 사유는 이번 수정본 게시에 대한 명시적 재승인 부재. 우회하지 않았고 기존 운영 버전 91을 유지했다.

운영 반영 전 기존 DB 존재·자료·백업·복구 권한을 확인하고 별도 환경에서 리허설해야 한다. 최신 [서버 운영 안내](../docs/care-commercial-server.md)와 [병원 파일럿·개인정보/계약·사고 대응 초안](../docs/care-pilot-operations.md)을 제공한다.

SOLAPI 계정/발신번호 인증·키 보관·충전과 한도·기관별 수신번호 승인이 필요하다. 어떤 외부 메시지 사업자와 실제 계약할지는 운영자가 정해야 하며 코드는 SOLAPI SMS 기준이다. 실제 요금/호스팅/DB/백업 비용은 계약·플랜 확인 전 확정하지 않았다.

법률·개인정보 전문가가 처리자/수탁자 관계, 건강정보 처리 근거·분리 동의, 위탁/국외 처리·권리 행사·보존/파기·사고 통지 의무를 검토해야 한다. 의료진은 질문·분류 규칙·관리기간·확인시간을 승인해야 한다. 향후 진단/예측 기능의 규제 해당성은 별도 검토 대상이다. 코드만으로 준수나 임상 안전을 확정하지 않는다.

## E. 미완료·제한

1. 실제 호스팅 D1 저장·스키마 적용·SSO 신뢰 헤더·운영 백업 복구·로그의 토큰 마스킹 확인.
2. 실제 SMS 발송·수신·과금·제공자 장애 검증. 정기 자동 재시도/전달 조회 스케줄러, 플랫폼 장애 알림·교대 감시 자동화. 현재 명확한 실패는 수동 재시도, 불명 결과는 수동 확인.
3. 직원 MFA/재인증·로그인 차단은 플랫폼 설정 확인 필요. 앱이 자체 MFA를 강제하거나 플랫폼 로그인 공격을 모두 제한한다고 주장하지 않음.
4. 더 강한 환자 추가 본인확인, 대리인 근거 검증, 서명된 세부 목적별 동의 수집·동의 철회 절차. 현재 연결 확인 체크가 모든 법적 동의를 대체하지 않음.
5. 보존일수 설정과 암호화 export 도구는 구현했으나 실제 삭제/파기·백업 키 회전·운영 감사 보관/외부 반출 정책 실행은 미완료. 임의 자동 삭제 없음.
6. 기존 브라우저의 배정·조치 전체 이력 자동 이관은 하지 않음. 기관별 데이터 검증·이관 계획 필요. 기존 기기 인증을 상용 권한으로 신뢰하지 않음.
7. 실제 동일 업무량의 도입 전후 시간 비교, 조치 필요 건수 대비 완료율의 병원 합의된 기준, 정밀한 서비스 이용량·계약별 할당량/결제는 추가 검증/구현 필요. 월간 ROI를 임의 추정하지 않음.
8. 병원별 질문 템플릿 편집기·EMR·파일 첨부·AI 요약/예측은 추가하지 않음. 실제 기기 iOS/Safari·스크린리더·독립 보안 진단 필요.

전체 작업을 ‘상용 운영 준비 완료’로 판정하지 않는다. 구현과 로컬 검증의 범위, 운영 적용 및 전문가 검토가 필요한 항목을 분리했다.

## 최종 보충
- 현재 선별 검증은 배포 Worker/운영 UI 15건 + 기존 로직 6건 + 기존 브라우저 흐름 13건 = 34건이다. 저장소 전체 테스트 실행이나 운영 환경 검증을 의미하지 않는다. 최종 산출물 재검증 결과는 아래에 추가한다.
- 검증되지 않은 1분 소요시간 문구를 환자·병원 소개에서 제거하고, 확인되지 않은 상담 이메일 대신 실제 서버 접수 경로를 연결했다. 소개 화면의 예시 수치는 합성 설명용임을 표시했다.

- 최종 공백 검사는 Windows CRLF를 허용하는 Git 설정으로 통과. 실제 운영 Site를 다시 조회해 공개 버전 91 유지 확인. 개발/테스트 서버와 대기 중인 소스 도구는 종료했다.
