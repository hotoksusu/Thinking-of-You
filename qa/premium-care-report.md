# 오늘안부 통합 UX/UI 및 서버 저장 고도화 결과

## 결과와 배포 상태
통합 화면과 서버 연동 코드를 구현하고 로컬 기능 검증을 수행했다. 운영 사이트는 버전 91을 유지한다. 자동 승인 검토가 이번 새 수정본의 외부 소스 동기화·배포를 별도 승인 대상으로 거절하여, 호스팅 DB 마이그레이션과 운영 배포는 아직 수행하지 않았다.

사용자의 추가 답변에 따라 기존 브라우저 저장만 표시하는 작업에서 신규 서버 저장/인증 연동까지 범위를 확대했다. 서버 설정·데이터 이전 절차와 미완료 운영 검증은 [운영 안내](../docs/care-server-operations.md)에 구분했다.

## A. 디자인
- Warm Premium Healthcare 공통 시스템: #315D50 Sage, #F7F5EF Ivory, #25302B Charcoal, 보조 텍스트 #58665E, 긍정 #E6F3EB.
- `.care-ui` 범위에만 컬러/표면/버튼/움직임 규칙을 적용해 기존 병원/관리자 스타일의 불필요한 변경을 피함.
- 곡률 18~28px, 약한 그림자, 44px 이상 터치 영역, 한 화면에서 한 주요 CTA 강조.
- 랜딩: ‘퇴원 후에도 이어지는 안부’, 전용 SVG 기록 모티브, 세 기능 요약. 개인정보·의료 안전 고지와 주요 메뉴 유지.
- 이용 안내: 메시지 → 병원 링크 → 내 상태 기록의 3단계 아이콘, 짧은 펼침 도움말. 일반 환자 체험 유도 제거.
- 오늘: 해·수평선·물결의 추상 상태 아이콘, 텍스트·테두리·선택 체크로 상태 구분. 기존 세부 통증/움직임/증상 질문 유지.
- 완료: 절제된 체크 피드백. 서버 저장 확인/기기 저장/샘플 기록을 각각 구분.
- 회복기록: 최근 7일의 실제 날짜축, 기록한 날/기록 없는 날, 날짜 선택과 상세 접근. 긴 반복 카드를 리스트로 정리.
- 병원안내: 내 병원/문의/도움의 구별 가능한 아이콘, 상황별 행 형태. 실제 등록 연락처·지도만 연결하며 119 즉시 접근 유지.
- 오류/빈 화면/로딩: 차분한 아이콘과 스켈레톤 유지, 실제 재시도 및 복귀 경로 제공.
- 모션: 선택/완료에 짧은 피드백. `prefers-reduced-motion`에서 움직임 제거.

## B. UX 및 데이터
- 기존 링크 → 기존 초대/권한 검증 → 기존 본인 확인 → 오늘. 인증된 환자는 불필요한 안내 생략.
- 신규 서버 링크 → 서버 초대 검증 → 본인 안내 확인 → 보안 쿠키 → 오늘.
- 일반 방문자 → 이용 안내와 링크 찾기 도움말. 인증 없이 실제 기록 접근 불가.
- 기존 기기 자료와 링크를 유지하고 자동 업로드하지 않음. 권한 있는 담당자가 실제 자료를 확인해 선택 복사할 수 있음.
- 서버 기록은 DB 저장 응답을 받은 후 완료 표시. 실패 시 입력 보존 및 재시도. 날짜별 유일 제약과 수정 시각 검증으로 중복/덮어쓰기 방지.
- 그래프는 기록 누락/통증 점수 없음/실제 0점을 구분. 없는 날의 선을 연결하거나 상승/호전 곡선을 만들지 않음.
- 종료된 관리의 읽기 화면과 병원안내 유지. 서버에서는 종료 환자의 신규 쓰기 차단.
- 병원 샘플은 개발 환경에만 보존. 운영 `/demo/**`는 샘플 클라이언트를 실행하지 않음.

## C. 서버 추가
- D1 논리 바인딩, 빈 스키마 마이그레이션, 서버 Worker API 구현. 실제 운영 데이터 seed 없음.
- 플랫폼이 검증한 ChatGPT 계정과 서버의 병원별 접근 목록을 사용. 기존 브라우저 역할값/로컬 환자 세션으로 서버 쓰기 권한을 만들지 않음.
- 해시로 저장하는 초대·세션 토큰, 보안 HttpOnly 쿠키, Origin 검사, 병원/환자 범위 검사, 초대 취소, 동의 확인 시각 저장.
- `/care/server`: 실제 병원/담당자/환자 등록, 확인한 기존 자료 복사, 링크 발급·취소·직접 복사, 서버 환자의 기록과 기존 리포트 컴포넌트 조회.
- 기존 로컬 병원/관리자 기능을 삭제하거나 임의로 서버 데이터와 섞지 않음. 기존 업무 후속 조치 전부의 서버 이관은 별도 후속 범위.
- 서버 운영자 이메일 환경 키 설정 완료. 호스팅 DB 실제 적용은 배포 승인 대기.

## D. 검증
- 360/375/390/430/768/1440px에서 핵심 CTA, 선택 표시, 도움말, 200% 글자 확대, 가로 넘침과 하단 메뉴 확인.
- 기존 초대·잘못된 링크·만료·빈 토큰·권한 불일치·세션 재방문·원본 링크 재이용, 저장 실패/수정/중복/입력 복원 확인.
- 기존 병원 역할별 리포트/권한/후속 조치, 병원 내비게이션, 관리자 정상/차단 경로 회귀 통과.
- 서버 API 실제 SQLite 검증: 인증 없는 요청·다른 병원 접근 차단, 잘못된 값·다른 Origin 거절, 저장 실패 롤백, 중복 방지, 수정 충돌, DB 재접속 후 데이터 유지, 초대 취소, 원본 가져오기의 누락값 보존.
- 운영용 UI + 서버 코드 + 테스트 DB 통합: 실제 저장 실패 시 완료 미표시, 재시도 저장, 수정, 날짜별 조회, 다른 브라우저에서 원본 링크 재접속 후 조회.
- 운영 병원 관리 UI: 실제 확인된 등록만 처리, 생성한 서버 링크 발급·취소, 브라우저 운영 저장소에 임의 seed 미생성.
- 기존 기기 링크 ↔ 서버 링크 전환에서 원본 기록 보존과 서버 쿠키 해제 검증.
- 실제 최근 7일 그래프에서 누락 점수와 날짜 공백 사이를 선으로 연결하지 않는지 확인.
- 운영 정적 출력의 전체 공개 데모 차단 검증.
- 순수 로직 6건 통과: 데이터 정합성·상태 규칙·회복 추이·보고서 등.
- TypeScript 검사 통과. 빌드 158개 페이지 내보내기 성공. 기존 ESLint 플러그인 누락 때문에 `--no-lint`로 빌드하며 린트 통과를 주장하지 않음.
- 새 SVG는 자체 코드이며 추가 이미지 다운로드/외부 이미지 URL/라이선스 의존 없음. 크기·비율을 미리 확보. 기존 랜딩 레이아웃 이동 자동 검사 0.1 미만.

## G. 미완료 및 후속 우선순위
1. 승인 후 새 소스 푸시·D1 마이그레이션·운영 배포. 실제 사이트 로그인과 호스팅 DB의 저장·조회·기관 분리 검증.
2. 운영자가 실제 병원·담당자 권한·환자 자료를 확인해 등록. 기존 기기 자료를 자동으로 신뢰하거나 가짜 환자를 서버에 생성하지 않음.
3. 병원별 동의 문구와 개인정보 보관/삭제·백업·감사 정책, 더 세밀한 직원 권한 및 기존 병원 후속 업무의 서버 이관.
4. 실제 iOS/Safari 발신·지도 앱·스크린리더 수동 검증. 운영 문자/카카오톡 자동 발송은 미구현이며 버튼으로 가장하지 않음.
5. 기존 ESLint 의존성 설치 복구. 현재 타입/빌드/브라우저 결과와 린트 한계를 별도로 보고.

## 자동 승인 검토 차단
검토 사유: 신규 서버 구현과 범위 확대는 승인됐지만 이번 수정본의 공개 Sites 소스 동기화·게시 승인은 없다고 판단. 다른 경로로 우회하지 않았다. 운영 버전 91 및 기존 데이터는 유지한다. 신규 호스팅 DB의 실제 적용·서버 저장의 운영 검증이 완료됐다고 주장하지 않는다.

## 최종 보충 검증
- 기존 전체 환자 여정 2건(390/1440px) 추가 통과: 뒤로 가기·새로고침·반복 수정·오류 복구·빈 기록·종료 상태·전체 기록 확장·실제 0점 표시.
- 기존 단계형 통증만 있는 기록은 임의의 3/6/9점으로 환산하지 않음. 점수가 없는 기록은 원래 표현과 ‘점수 없음’을 유지하며 그래프에서 비워둠.
- 주요 텍스트 팔레트의 명도 대비 검사 통과: 본문 12.54:1, 보조 설명 5.54:1, 주요 버튼 7.47:1, 선택 상태 6.54:1. 결과 qa/premium-accessibility.json. 전체 접근성 인증을 의미하지 않음.
- 서버 세션이 만료됐을 때 다른 기존 기기 환자의 화면으로 자동 전환하지 않도록 분리. 원본 기기 링크를 명시적으로 다시 열 때만 해당 경로로 연결.
- 불필요한 데모 캐릭터 이미지 preload 제거. 새 서버 Worker는 단일 ESM 파일로 묶어 산출물 자체를 검증.


- 최종 변경 후 배포용 단일 Worker 산출물로 서버·운영 화면 테스트 6건 재실행: 6건 통과, 실패 0건. 전체 선별 회귀 검증은 25건이며 저장소 전체 테스트 실행을 의미하지 않음.
- 병원 서버 관리의 환자 기록은 읽기 전용 상세 목록으로 표시. 환자 전용 입력 화면으로 이동하는 링크 제거.
- 최종 정적 빌드 완료 및 git diff --check 통과. 운영 D1 적용과 실제 호스팅 인증 검증은 미완료.
