# 랜딩페이지 진입 UX 추가 개선 — 2026-10-14

## 변경 내용
- 랜딩의 시작 CTA는 `/patient` 이용 경로 확인 화면으로 연결.
- 유효한 기존 환자 세션: 기존 `/app/patient` 오늘 화면으로 이동.
- 미인증 방문자: 링크 이용 방법, 링크 미수신/분실 시 병원에 문의하는 방법, 샘플 체험, 랜딩 복귀 경로 제공.
- 만료된 세션: 이용 경로 화면에 다시 연결하는 방법 표시. 저장 정보 오류도 별도 안내하고 기존 기록을 삭제하지 않음.
- 랜딩은 인증 없이 이용하는 홍보 화면으로 유지. 로그인한 환자도 랜딩을 볼 수 있고 시작 CTA를 누르면 환자 화면으로 이동.
- 랜딩과 `/patient`에 전달된 `token`은 빈 값까지 기존 `/i` 인증 경로로 전달. 정상 링크의 기존 본인 확인·환자 연결 로직은 변경하지 않음.
- 만료/잘못된 링크: 기존 상황별 오류 메시지에 링크 찾기·새 링크 요청 방법을 기본 노출. 서비스 이용 경로/랜딩 복귀 링크 추가.
- 실제 가입 서비스로 오해할 수 있는 랜딩의 ‘가입 및 이용 시작’ 메뉴 항목 제거. 기존 `/start` 라우트는 삭제하지 않음.

## 체험 환경 보호
- 기존 `/demo/patient` 및 별도 샘플 데이터 저장소를 재사용. 실제 환자 데이터에서 샘플을 가져오지 않음.
- 모든 환자 체험 화면에 실제 기록 저장·병원 전송이 없음을 명시.
- 샘플 입력은 샘플 저장소에만 반영하고 실제 환자/병원 저장소·인증을 변경하지 않음.
- 체험 분석 이벤트에서 실제 환자/병원 세션을 조회하지 않도록 수정. 체험 기록이 실제 감사 기록에 섞이는 경로 차단.
- 미구현 가입·링크 발급·병원 검색 버튼 추가 없음. 링크 발급은 병원에 요청하는 방법만 안내.

## 테스트 범위
- 신규 방문 → CTA → 이용 경로 → 체험 → 뒤로 가기 → 새로고침 → 랜딩 복귀.
- 정상 링크 → 기존 본인 확인 → 오늘 화면.
- 로그인한 환자의 랜딩 재방문 → CTA → 오늘 화면, 새로고침.
- 만료/잘못된/빈 토큰 → 각각 오류와 링크 재발급 방법, 새로고침.
- 만료 세션/손상된 저장 정보 → 적절한 안내와 이용 경로.
- 실제 세션이 있는 상태에서 샘플 입력 후 실제 기록·인증·초대·분석·감사 저장소가 바뀌지 않는지 비교.
- 테스트에는 자동 생성된 샘플과 테스트용 초대만 사용. 운영 환자 데이터는 사용하지 않음.

## 배포 상태
새 수정본의 외부 소스 동기화·배포는 자동 승인 검토에서 명시적 게시 권한 부족을 이유로 거절됨. 현재 운영 사이트 버전 90은 유지하며, 이번 변경은 로컬에 있음.

## 제약
실제 병원에서 문자를 발송하는 외부 시스템, iOS/Safari, 실제 운영 환자의 인증을 수동 확인하지 않음. 기존 인증 방식과 저장 구조를 유지했으며 서버 인증이나 실제 링크 발급 기능을 신설하지 않음.
