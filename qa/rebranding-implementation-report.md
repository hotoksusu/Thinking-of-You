## 수정된 소스와 재사용 기능

- 브랜드 및 홈페이지는 src/lib/care-brand.ts, src/components/care-brand-logo.tsx, src/components/danyeon-landing.tsx, app/layout.tsx, app/danyeon.css, app/manifest.ts, app/hospital과 app/company에서 구현했다.
- 환자 UX는 src/components/patient-home.tsx, patient-care-mvp.tsx, patient-server-gate.tsx와 관련 안내·오류 컴포넌트를 변경했다. 기존 초대 경로, 단일 세션, 1일 1건 저장, 기록 조회·그래프를 재사용했다.
- 병원과 운영은 app/care/server/page.tsx, src/components/server-operations.tsx, care-operator-overview.tsx, app/pilot/page.tsx와 server/care-api.mjs, care-operations.mjs, care-sms.mjs를 변경했다. 기존 테넌트 권한, 업무 업데이트, 감사 이벤트, CSV와 SMS 큐를 재사용했다.
- 데모와 검증은 app/demo, scripts/danyeon-demo.mjs, tests/helpers/care-http.mjs, tests/danyeon-v2.mjs와 기존 SMS 모의 테스트를 사용했다.
- 상품 안내·팔레트·메타데이터와 템플릿 미리보기는 중앙 설정에서 읽는다. 이전 브랜드는 운영 기본값, 비핵심 가족·기기 기능, 예전 URL과 리소스, 기록과 정책 자료, 기존 실제 발송 템플릿에 남아 있다. 비공개 신규 핵심 진입점은 다녀온 설정을 사용한다.

## 범위와 운영 전 조건

AI 진단·치료 권고·새로운 임상 기준·회복곡선, EMR, 보호자 확장, 앱, 결제와 자동 청구는 개발 범위에서 제외했다. 관리 프로그램의 일일 일정과 병원 승인 기간을 재사용했다. 병원별 임의 요일 일정과 질문 편집기는 이번 작업 범위 밖이다. 법률 판단, 상표 등록 가능성, 실환자 운영 승인, 실제 기기 검증 범위는 [파일럿 승인 체크리스트](pilot-readiness-checklist.md)에 기록했다.

## 유지보수와 롤백

두 브랜드 화면을 임시로 유지하므로 공개 전환 시 메타데이터와 리소스, 링크·리포트와 승인된 템플릿을 한 번 더 확인해야 한다. 안내 링크와 기존 ID 경로를 유지했고 운영 DB 스키마 변경이 없다. 합성 데모 데이터는 프로세스와 함께 폐기된다.

로컬에서는 비공개 환경 변수를 해제하고 기존 브랜드로 다시 빌드할 수 있다. 전체 코드 철회가 필요하면 기존 작업을 별도로 보존한 뒤 기준 소스 또는 승인 직전 아티팩트로 되돌린다. 운영 전환이 승인된 뒤 장애가 발생하면 Sites의 검증된 이전 버전과 당시 환경 변수로 돌리고 환자 링크·권한·CSV 동작을 확인한다. 운영 DB 복구는 별도로 승인된 복구 절차를 사용한다.

실행 방법은 [브랜드 설정 및 데모 실행](../docs/brand-config.md), 결과와 한계는 [테스트 보고서](rebranding-test-report.md)에 있다.
