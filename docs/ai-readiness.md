# 오늘안부 AI-Readiness

## 현재 범위

오늘안부는 현재 AI 의료서비스가 아니다. 환자 입력, 병원 운영 맥락, 규칙 기반 표시 우선순위, 의료진의 실제 후속조치 결과를 분리해 기록하는 제품 아키텍처를 제공한다. `demo-v1` 규칙은 진단·예측·의료 위험 점수가 아니며 제품 워크플로 데모용이다.

## 현재 데이터 경계

- `Patient`는 사람/연락처, `PatientEpisode`는 한 번의 수술·퇴원 후 관리 맥락이다.
- `CheckInEvent`는 환자가 입력한 원자료다. 미응답은 0이 아니며, `none`과 `unanswered`를 구분한다.
- `FollowUpEvent`는 병원이 한 조치와 그 결과를 구조화한다.
- `ClinicalWorkflowDecision`은 화면에 표시된 우선순위·이유와 직원 판단을 함께 남긴다.
- 각 이벤트에는 source/provenance를 둔다. Demo와 운영 범위를 `dataScope`로 구분한다.
- Research 응답은 운영 Care 데이터와 결합하지 않으며 기존 별도 저장·동의 경계를 유지한다.

## 다음 단계

1. 이벤트 스키마 버전과 변경 이력을 명시한다.
2. Episode 활성/종료 상태와 예상 체크인 스케줄을 추가해 미응답을 정확히 계산한다.
3. 권한, 감사 로그, 보존 기간, 삭제 요청, 데이터 최소화 정책을 운영 백엔드에 적용한다.
4. 병원별 설정과 규칙 버전을 배포 단위로 관리한다.

## Phase 1 — 분석 준비

- 비식별 제품 워크플로 지표와 데이터 품질 모니터링
- 결측/미응답/중복/시간대 처리 기준 고정
- 의료진 후속조치 결과 taxonomy 검증
- 의료적 성과가 아닌 운영 지표의 정의와 검수

## Phase 2 — 검증 연구 준비

- 별도 연구계획, 명시적 동의, IRB/법률·보안 검토가 완료된 데이터만 사용
- rule baseline과 후보 모델을 오프라인으로 비교하고 편향·안전성·설명 가능성을 평가
- 민감정보 접근을 최소화하고 연구 데이터셋을 운영 서비스에서 논리·물리적으로 분리
- 임상적 유효성 주장은 전향적 검증 없이는 하지 않음

## 장기 가능성

충분한 품질·동의·거버넌스·임상 검증을 갖춘 뒤에만 요약 보조, 업무 큐 정리 보조, 개인별 회복 패턴 탐색 같은 기능을 검토할 수 있다. 모델 출력은 의료진 판단을 대체하지 않으며, 인간 검토·실패 대응·버전 추적·성능 저하 모니터링이 선행되어야 한다.

## 명시적 비범위

현재 구현에는 AI 모델, 외부 AI API, 챗봇, 자동 진단, 위험 예측, 치료 추천이 없다.
